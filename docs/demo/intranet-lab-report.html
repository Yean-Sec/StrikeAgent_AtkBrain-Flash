Executive Summary

对授权目标 portal.lab.internal（示例内网靶场）及其解析出的同机服务面开展授权渗透测试。攻击路径从公开静态站的情报泄露切入，扩展到数据侧同机服务群，最终在 OmniDB 数据库管理工具上完成权限落地：

  • DataHub 数据中台默认口令 admin / lab-default 进入超级管理员；

  • OmniDB 默认口令 admin / admin 进入后台；

关键结论

  • 严重OmniDB 监控脚本沙箱逃逸实现远程命令执行，服务器权限已到手（omnidb 用户，canary 复验通过）；

严重

DataHub 默认口令 admin / lab-default 进入超级管理员

类型 admin_access 状态 已验证

① 简介 / 技术成因

DataHub 数据中台（data.lab.internal）的登录防护存在两个可叠加缺陷：① 验证码接口 /api/auth/captcha 直接返回 SVG 明文四位数字，脚本一行 sed 即可解析，验证码形同虚设；② 默认口令 admin / lab-default 未修改。两者叠加使「自动化登录超级管理员」完全可行。

登录成功：POST /api/auth/login → code=0 + accessToken（JWT，UID=，角色 SuperAdmin）。随后 GET /api/user/detail → username=admin、roles=[{code:SuperAdmin}]；GET /api/user → total=2（admin, user_a）；GET /api/dataset/count → 6。即全站用户、角色、数据集、上传文件清单均可读取（未改业务数据、未灌库）。

关联性：本条为攻击链核心枢纽 —— SuperAdmin 会话后续支撑上传+未授权读、SVG XSS、垂直越权差分、密码哈希回显，并最终通过前端硬编码的数据库工具入口导向 OmniDB 命令执行。

③ 修复方式

⚠ 立即缓解
  • 立即修改 admin 默认口令为强口令，并对全站账号做弱口令排查（联动密码 MD5 回显可离线比对）。
  • 修复验证码：服务端会话绑定、不可从接口直接读出明文（图形混淆/行为验证/图片验证码）。
  • 对 /api/auth/login 增加登录失败次数限制与账号锁定；评估对公网做来源限制。
✔ 根治
  • 口令策略落地：复杂度 + 有效期 + 首次登录强制改密；定期弱口令扫描纳入运维基线。
  • 验证码服务端强校验，任何客户端可见的「答案字段」必须移除。
  • 敏感接口最小暴露：user/detail、role/page 等按需返回字段（联动脱敏）。
  • 登录行为审计 + 异常（同源高频登录）告警。
